## 13-Week Plan

| Week | Course Topic | Project Task (applies to every project) | Deliverable | Marks |
| --- | --- | --- | --- | --- |
| 1 | Introduction to Software Engineering and Process Models | Choose a process model (Agile/Scrum, Waterfall or Incremental) and justify it. Write a one-page project proposal. Create the Git repository with a README. | Project proposal, process-model justification, repository link | 4 |
| 2 | Requirements Engineering | Identify stakeholders and elicit requirements. Write 10 or more functional and 5 or more non-functional requirements and 8 or more user stories with acceptance criteria. | Draft SRS (Sections 1-3), user stories | 8 |
| 3 | Requirements Validation and Project Planning | Prioritise requirements (MoSCoW), estimate effort, build a product backlog, a 13-week plan and a risk register. | Backlog, schedule, risk register, estimate | 6 |
| 4 | System Modelling with UML | Produce a use case diagram, class diagram, sequence diagram for the main flow, and an activity diagram. | UML model set | 8 |
| 5 | Software Architecture and Database Design | Choose and justify an architectural style. Draw the component/deployment diagram and design the database (ERD and schema). | Architecture document, ERD, schema script | 8 |
| 6 | Design Patterns and UI/UX Design | Apply at least two design patterns with justification. Build wireframes for the key screens and apply SOLID principles to one module. | Design-patterns note, wireframes | 6 |
| 7 | Implementation I and Version Control | Set up the project structure and coding standard. Implement the first core module using feature branches, meaningful commits and pull requests. | Working module 1, Git history | 6 |
| 8 | Mid-Semester Review: Prototype Demo | Demonstrate a working prototype of the core flow. Present progress against the plan and revise the backlog from feedback. | Live demo, progress report | 10 |
| 9 | Implementation II, Refactoring and Code Quality | Implement the remaining major modules. Run a peer code review, refactor code smells and run a static analysis tool. | Modules 2+, review log, static-analysis report | 6 |
| 10 | Software Testing | Write a test plan. Create unit tests and integration tests (target 60% or more coverage) and run a system test against the requirements. | Test plan, test cases, coverage report, defect log | 8 |
| 11 | Secure Development and DevOps | Perform threat modelling (STRIDE) and check against the OWASP Top 10. Set up a CI pipeline that builds, tests and scans on every push. Deploy to a test environment. | Threat model, CI pipeline, deployed build | 8 |
| 12 | Maintenance, Documentation and Software Metrics | Handle one change request and record its impact. Write the user manual and technical documentation. Collect metrics (size, complexity, defect density). | Change request, documentation, metrics report | 6 |
| 13 | Final Demonstration, Report and Reflection | Present the finished system, submit the final report and run a peer assessment. Reflect on the process and lessons learned. | Final demo, final report, reflection, peer review | 16 |
